# 開発フェーズとスキル

- 日付: 2026-11-13
- 対象: game-poc の開発運用
- 利用者は、計画で Issue を作り、実装では対象 Issue を進め、報告・レビューではその差分を話し合う流れを希望した。
- PR #50 のマージ報告後、利用者が対象を指定する前に #49 の残作業へ着手してしまった。マージ報告だけで次の Issue に進まず、対象とフェーズの指示を待つ。
- Matt Pocock の `to-spec`、`to-tickets`、`implement`、`code-review` を各フェーズの候補として確認した。`implement` は対象の実装後、レビューとコミットを行う。利用者と差分を話し合うタイミングはプロジェクトの運用で明示する。
- Issue トラッカーやラベルに関する同スキル群のリポジトリ設定は未確認。未設定時やスキルを利用できない場合は、黙って別の運用に切り替えず、状況と代替案を伝える。
