# Issue 単位の開発運用

日付: 2026-11-05
対象: game-poc の開発作業

ユーザーは Issue、PR、セッション、ブランチ、worktree の分け方について相談し、次の運用を採用した。

- 作業 Issue ごとにブランチ、PR、セッションを分けることを原則とする。ブランチ名の例は `codex/16-headless-tests`。
- Issue が大きい場合は、レビューしやすい複数 PR に分けられる。Issue の完了条件を満たす PR に `Closes #番号` を使う。
- worktree は、並行作業や変更を残した切り替えなど、作業場所の分離が必要なときに使う。すべての作業に必須とはしない。
- worktree の片付け前には、所有者と追跡済み・未追跡・無視対象の変更、およびブランチの状態を確認する。
- 次の実装候補は #16 のテスト基盤。その後 #17 の PR 向け CI にテストを組み込む。
