# ggg による Godot 依存管理

- 日付: 2026-11-05
- 対象: GdUnit4 の再現可能なセットアップと Pages CI

## 確認した事実

- ggg 0.6.0 の macOS arm64 バイナリを scratch プロジェクトで評価した。
- `ggg.toml` で Godot 4.7.2 stable と GdUnit4 6.2.3 の archive URL、SHA256、展開先を指定し、`ggg.lock` に archive hash が記録された。
- scratch 環境で同期後に Godot のアセット import と GdUnit4 の 3 テストが成功した。
- ggg は同じ dependency 名の既存ファイルが一致しない場合、`--force` を要求して同期を停止する。既存 addon は強制上書きしない。
- ggg 0.6.0 の Linux x86_64 release archive は公式 GitHub release から取得し、archive SHA256 `769586eaec6c4a80efbe05f28f108da029058db01fdd326172b961f0b803249a` を検証する。

## 判断

- 手製の GdUnit4 展開スクリプトを廃止し、依存の宣言と lock を ggg に集約する。
- `make setup` は `ggg sync --godot $(GODOT)` を実行し、ggg のパスは `GGG` で上書き可能にする。
- Pages workflow は ggg 0.6.0 の Linux x86_64 archive hash を検証してから利用する。
- ggg 管理外の既存 `addons/gdUnit4` と project-owned addon は保護し、競合時はユーザーが内容をバックアップして判断する。

## 検証結果

- scratch の同期、import、3 件の GdUnit4 テストに成功。
- scratch の競合ケースで既存 addon を残したまま同期が停止することを確認。
- scratch の Godot はユーザー設定領域への書き込み警告を出したが、テスト結果は全件成功。
