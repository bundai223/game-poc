# Issue #11 3D Vehicle Craft PoC

- 対象: https://github.com/bundai223/game-poc/issues/11 （上位Epic #3、ロードマップ #1）
- 利用者の依頼: 動作確認済みの #30・#31 に続き、Issue #11を進める。
- 仕様上の選択: 1m単位のXZグリッド、ブロックと車輪の2部品、固定接続したブロック群、左右差動で駆動する2個以上の車輪、ローカルの `user://vehicle-craft.json` を用いる。
- 部品モデル: `PartData` に種別 (`block` / `wheel`) を加え、種別なしの既存version 1 JSONは `block` として読み込む。`VehicleData` が部品IDと固定/ヒンジ接続を保持し、JSON往復を行う。NodeやSceneTreeを参照しない。
- Node変換: `vehicle_adapter.gd` が固定接続されたブロック群を1個の `RigidBody3D` と複数の箱形状にまとめる。車輪は独立した `RigidBody3D` と `HingeJoint3D` モーターにする。旋回は車体中心の左右でモーター速度に差をつける。
- 操作: 2D画面の `3D Craft` から移動。選択・ブロック追加・車輪追加・移動・削除、試走/編集、保存/読込を行う。走行はキーボードW/A/S/Dと画面ボタンに対応する。
- 試走条件: 連結したブロックが1個以上あり、すべての車輪がブロックにヒンジ接続され、車体中心の左右両側に少なくとも1個ずつ車輪があること。
- 確認: `make test` 31件すべて成功。`make export-web` 成功。`npm run test:e2e` 3件成功（2D描画/Reset、非ゼロ接触ID、2Dと3Dの画面遷移）。車体前進、車輪回転、旋回はGodot物理フレームの統合テストで確認した。
- 未確認: 実機Android/iPadのタッチ操作、実機の3D描画/性能、ブラウザの保存/読込UI操作。E2Eでは保存/読込を直接検証していない。
- 制約: 形状は立方体ブロックと円筒車輪のみ。ブロックは個別物理剛体ではなく一体の車体として扱う。高度な関節、素材編集、クラウド保存は対象外。
